## ABI corrections and documentation discrepancies

SDK 1.7.3 header is the authority. `CameraAcquire` takes a client-ID string. The current `ALL_ROTATION` mask is 11; there is no separate REFERENTIAL bit in that header. `SIMCONNECT_DATA_PBH` uses three floats, not doubles. `SIMCONNECT_DATA_CAMERA` is 84 bytes, and `SIMCONNECT_RECV_CAMERA_DATA` is 96 bytes. Initial C# orientation declarations were corrected after a live packet-size check; no camera-setting calls were made with the incorrect structure.

The online CameraGet documentation contradicts itself about acquisition requirements. An Asobo clarification says SU6 returns the currently active camera. This is consistent with passive read observations: [CameraGet clarification](https://devsupport.flightsimulator.com/t/cameraapi-cameraget-behavior-requires-clarification/17697).

The API exposes a single add-on camera and CameraGet has a referential argument but no object-ID or secondary-camera selector. We have not found a documented function to read the world position of a hidden, independently selected add-on camera. We do not treat acquire/query/release as invisible or valid target tracking without a successful runtime test.

WORLD altitude is logged in raw meters with its datum marked unverified. It must not be fed to an MSL altitude controller without validating the conversion. A target reference falling back to own aircraft is rejected; latitude zero alone is not invalid because flight over the equator is valid.
